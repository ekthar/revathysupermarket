# Swiggy-parity overhaul: fix pass for variant stock, order persistence, and analytics (v2)

This v2 pass addresses all 6 issues from the initial review. The cart validate endpoint now accepts `variantIds` and the reconciliation logic checks variant-level stock before allowing items to remain. `variantLabel` flows from checkout form through the validation schema into the `OrderItem` row. The time-of-day rail is a client component with `useState`/`useEffect` so it always reads fresh time. `CART_VIEWED` depends on `items.length` with a ref guard. The trending API returns actual popular products for the zero-result suggestions component. The PDP respects `isDefault` for variant selection.

Watch for: the `popularProducts` state in global-search uses an `as unknown as Product[]` cast that silently drops type safety if the trending API response shape drifts (possible). No new blocking concerns.

**Verdict**: APPROVED

## High-level view

The variant stock validation is properly layered: the validate endpoint exposes a parallel `variants` array, and the cart-provider reconciliation maps variant IDs to their stock, dropping items or clamping quantities accordingly. The variant-not-found case (deleted variant) also correctly removes the item.

The order persistence fix threads `variantLabel` through three layers (checkout form submission, Zod schema validation, Prisma `create`) so the column that was previously always NULL now captures the selected variant's label at order time.

## Type safety gap in popular products

The global-search component holds `popularProducts` as `SearchProduct[]` (a `Pick` of 8 fields from `Product`). The `ZeroResultSuggestions` component declares its prop as `Product[]`. The cast `popularProducts as unknown as Product[]` bridges this at the call site. Today, `ZeroResultSuggestions` only accesses `id`, `slug`, `name`, `image`, `price`, `discountPrice` — all present in `SearchProduct`. But the double-cast eliminates compiler protection against future field access. The trending API does return additional fields (`description`, `popularity`, `isFeatured`) so the runtime risk is minimal for now, but a prop type narrowing on `ZeroResultSuggestions` would restore compile-time safety.

</details>
